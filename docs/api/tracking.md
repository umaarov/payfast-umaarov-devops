# tracking-service API

Port 8084. Stores the history of every parcel as an append-only list of events in its own PostgreSQL database.

`GET /api/tracking/{trackingNumber}` is public and needs no API key. `/internal/**` is for other services only and is never routed by the gateway.

## Statuses

| Status | Meaning | Closes the parcel |
| --- | --- | --- |
| `CREATED` | Order accepted | no |
| `COURIER_ASSIGNED` | A courier was assigned | no |
| `PICKED_UP` | Courier collected the parcel | no |
| `IN_TRANSIT` | On the way | no |
| `DELIVERED` | Handed to the recipient | yes |
| `DELIVERY_FAILED` | Attempt failed; can be retried | no |
| `CANCELLED` | Order cancelled | yes |

Rules:

- The first event of a parcel must be `CREATED`, and `CREATED` can happen once.
- After `DELIVERED` or `CANCELLED` no more events are accepted.
- Events are sorted by `occurredAt`, then by arrival time, so a late event lands in the right place.
- Events are never updated or deleted.

## Tracking number

12 characters: `LG` followed by 10 random uppercase letters or digits, generated by order-service. The service accepts 8 to 32 characters from `A-Z0-9`.

## Public endpoint

`GET /api/tracking/{trackingNumber}`

```json
{
  "trackingNumber": "LGK4M9X2PQ7A",
  "status": "PICKED_UP",
  "updatedAt": "2026-11-25T10:00:00Z",
  "events": [
    { "status": "CREATED", "description": "Order accepted", "location": "Tashkent", "occurredAt": "2026-11-25T08:00:00Z" },
    { "status": "COURIER_ASSIGNED", "description": "Courier assigned", "location": "Tashkent", "occurredAt": "2026-11-25T09:00:00Z" },
    { "status": "PICKED_UP", "description": "Parcel collected", "location": "Tashkent", "occurredAt": "2026-11-25T10:00:00Z" }
  ]
}
```

The response contains no customer name, address, phone, or internal identifiers. 404 for an unknown number, 400 for a malformed one.

## Internal endpoint

`POST /internal/tracking-events`

```json
{
  "eventId": "7d1c4a2e-2f4b-4a56-8d68-0c1b8f6f9a10",
  "trackingNumber": "LGK4M9X2PQ7A",
  "status": "COURIER_ASSIGNED",
  "description": "Courier assigned",
  "location": "Tashkent",
  "occurredAt": "2026-11-25T09:00:00Z"
}
```

`eventId` is chosen by the caller and makes retries safe. `description`, `location` and `occurredAt` are optional; `occurredAt` defaults to the arrival time.

| Status | Meaning |
| --- | --- |
| 201 | Event recorded |
| 200 | An event with this `eventId` already exists; it is returned unchanged |
| 400 | Validation error, unknown status |
| 409 | Transition rule violated |

Errors use RFC 7807 problem details.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `SERVER_PORT` | `8084` | HTTP port |
| `TRACKING_DB_URL` | `jdbc:postgresql://localhost:5432/tracking` | JDBC URL |
| `TRACKING_DB_USER` | `tracking` | Database user |
| `TRACKING_DB_PASSWORD` | empty | Database password, never committed |

## Running alone

```powershell
$env:TRACKING_DB_PASSWORD = "choose-a-local-password"
docker run -d --name tracking-db -e POSTGRES_USER=tracking -e POSTGRES_PASSWORD=$env:TRACKING_DB_PASSWORD -e POSTGRES_DB=tracking -p 5433:5432 postgres:17
$env:TRACKING_DB_URL = "jdbc:postgresql://localhost:5433/tracking"
.\mvnw.cmd -pl tracking-service spring-boot:run
```
